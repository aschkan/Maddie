Thesis · Evidence-dashboard redesign · for Evanthia

Maddie as a visualization system — not a smart app

No overall safety score. No "recommended route". Coordinated small views where the user compares the actual evidence themselves, in the style of the Visual Decision-Making for Nature-Based Solutions project and Franconeri's chart-chooser method.

Framing shift

From "safety score" to "evidence exploration"

The earlier mockups still assumed Maddie should hand the user a verdict (72 Favourable, ★ Recommended Route A). The reference project refuses that. It shows what is known about an area or a route — reports, lighting coverage, nearby places — as separate factors, each in the chart type that fits its data. The user decides.

1 · Decompose, don't aggregate

No single score. Each factor (lighting, reports, nearby places, time) is its own view. Munzner Ch. 3: aggregation hides the structure users need to see.

2 · Chart matches data type

Categorical → bar chart. Continuous → histogram. Comparison → dot plot small multiples. Spatial → map. From Franconeri's L2 "Vis Chooser per Data Type".

3 · Brush and link, don't filter

Select a bar → highlights the related points on the map and the related slice on every other chart. One click, five views update. Munzner Ch. 12.

4 · Show the unknown

Where lighting data is missing, it's a visible striped category — not hidden, not imputed. "Missing lighting stays unknown."

5 · Reports are context, not inputs

Community reports describe a dataset of lived experience. They are shown alongside routes, not folded into a route score.

6 · Scientific honesty on the page

"CONCEPT MOCKUP · Synthetic example data". "Observed reports describe this dataset, not incident risk." Every caveat lives on the page itself.

Board 01

Explore urban mobility evidence — the overview dashboard

Replaces the current blank-map opening screen. One map, four coordinated small views. Selecting a neighbourhood on the map, or a bar on any chart, highlights the related records everywhere — the Munzner / Franconeri brush-and-link pattern. No safety score anywhere.

What's here

  • Map (center top) — community reports as purple dots, nearby places as pink hearts, selected neighbourhood outlined in blue. No safety heatmap, no "score" colouring
  • Bar chart (top right) — report counts by type; purple = selected area, gray = all displayed records. Same chart Franconeri recommends for categorical comparison
  • Histogram (bottom left) — reports by hour of day, with a brush selector that re-filters every other view
  • Stacked bars (bottom center) — lighting coverage by neighbourhood: lit / unlit / unknown. "Unknown" is a visible category, not hidden
  • Histogram (bottom right) — how close reports fall to the user's selected route (if one is chosen)

Why it's a visualization system now

  • Chart matches data type — Franconeri L2: categorical → bar; continuous → histogram; part-to-whole → stacked bar. Every panel is the chart its data asks for
  • Linked highlighting — click Harassment bar → every chart filters to harassment. Click the map area → every chart re-scopes. Munzner Ch. 12
  • Honest about uncertainty — missing lighting data is a striped "Unknown" stripe, not imputed
  • Framing is scholarly — "CONCEPT MOCKUP · Synthetic example data" and the caveat line are on the page itself
  • No safety verdict — nothing says 72, Favourable, Recommended. The user interprets the evidence
Franconeri L2 · chart chooser Munzner Ch. 7 · arrange tables Munzner Ch. 12 · linking NbS paper · dashboard pattern
Board 02

Compare route evidence — three routes, five factors, no score

Replaces the current route cards. One dot plot per factor; one row per route; a timeline below showing where differences occur along each path. The header line is the thesis statement: compare individual factors; there is no overall safety score.

What's here

  • Small map (left) — three route geometries as line styles the user can tell apart without colour alone (solid / dashed / dotted)
  • Five dot plots (right) — one per factor: Time, Mapped lit %, Unknown lighting %, Nearby places, Parkland metres. Each row is a route; each dot is where that route sits on that axis
  • Timeline tracks (bottom) — one row per route showing lighting coverage, hearts, reports, park/underpass arcs along the progress axis. Brush an interval → map highlights the matching segments
  • Selected interval panel (right) — what's known about the brushed stretch of Route B, with an Example narrative clearly labelled "EXAMPLE — NOT A REAL REPORT"
  • Trade-off slider — "Maximum extra time: 10 min" filters routes shown; the note says "does not re-score"

Why no overall score

  • Scores hide trade-offs. Route B is best on lighting but worst on parkland. A single number collapses that
  • Dot plots make differences visible. Franconeri L2 — when you want to compare three things on five axes, five dot plots side by side is the shape
  • Lived experience ≠ risk model. The qualitative narrative is shown next to the quantitative tracks, labelled as such, and never aggregated
  • The thesis defence — Evanthia's concern was Maddie performing certainty it doesn't have. "No overall safety score" in the header turns that into a feature
Franconeri L2 · dot plots Munzner Ch. 6 · facet by factor Munzner Ch. 10 · trellis NbS paper · trade-off slider
Board 03

Explore a single area — the neighbourhood deep-dive

When the user clicks a neighbourhood on Board 01, this view opens. Same chart-chooser logic: distribution → histogram, time series → line, categorical → bar, part-to-whole → stacked bar. Still no score. Still a dataset, not a verdict.

Chart choices by data type

  • KPI strip (top) — counts, not scores. Big numbers to anchor the view; the colours tag the data source, not a verdict
  • Line chart (left middle) — Franconeri L2: time series over 12 months → line, one line per category
  • Heatmap (right middle) — Franconeri L2: two categorical axes (hour × weekday) with a count → heatmap. The current hour is outlined
  • Provenance table (bottom left) — the raw truth about where each chart's data came from, by row
  • Bar chart (bottom right) — neighbourhoods compared on reports-per-km-of-road, so a bigger area isn't automatically "worse"

What stays off this screen

  • No colour-coded "safety" overlay on any count
  • No "Favourable / Mixed / Look closer" labels — a count is a count
  • No forecast or prediction — the time series ends at today
  • No star rating, no recommendation sentence
  • The provenance table makes clear which data is observed, which is modelled, which is missing
Franconeri L2 · time series + heatmap Munzner Ch. 10 · attribute-driven layout Munzner Ch. 13 · reduce aggregate

What changed from the earlier mockups to these

Dropped — the single safety score (72 Favourable) · "star Recommended Route" · colour-coded safety heatmap over neighbourhoods · "Look closer / Mixed / Favourable" verdicts in the UI chrome · the stacked contribution bar that assembled a score · the day/night gradient framing as a safety predictor.

Kept — brush-and-link coordinated views · priority sliders (now reframed as filters, not weights that produce a score) · map legend persistence · explicit shape differentiation (hearts for places, dots for reports) · lighting glow on well-lit road segments.

Added — dot plot small multiples for route comparison · multi-track timeline aligned on a 0–100% progress axis · stacked bar with "Unknown" as a visible category · scientific caveats on the page itself · "EXAMPLE — NOT A REAL REPORT" badges on illustrative narratives · data-provenance table.

The thesis argument changes with these mockups: Maddie is no longer a smart app that tells you where it is safe. It is a visualization system that shows the user what is known and unknown about the places they move through, in the chart type each piece of knowledge asks for. That is a defensible research contribution. A black-box safety score is not.
